Release Announcement v1.10.0

We are pleased to announce that the Apache YuniKorn community has voted to release 1.10.0. Apache YuniKorn is a standalone resource scheduler, designed for managing and scheduling Batch and Data workloads on container orchestration frameworks like Kubernetes for on-prem and on-cloud use cases.

Overview​

The Apache YuniKorn community has resolved 95 JIRAs in this release.

Release manager: Wilfred Spiegelenburg

Release date: 2026-10-06

New security mailing list​

As part of the increased AI reports of security issues YuniKorn has created the security@yunikorn.apache.org mailing list. Documentation updates have been made to show the new reporting procedure. See YUNIKORN-3476 for further details.

Committers and PMC can subscribe the mailing list using their @apache email address.

Highlights​

Kubernetes 1.36 support​

Apache YuniKorn 1.10.0 adds support for Kubernetes 1.36. See YUNIKORN-3295 for details.

Retry on K8s failures​

Kubernetes API server failures are retried for specific use cases. Retries are based on the failure type returned by the K8s client. Not all failures can or will be retried. See YUNIKORN-2804 for details.

Web UI v2 turned off by default​

The web UI v2 which has been turned off by default. The current version is not mature enough for consumption by the end user. When development resumes the new queue UI will be turned back on again.
See YUNIKORN-3302 for details.

Double compression on metrics endpoint​

The Prometheus handler implements compression on the endpoint that it serves. The implementation of REST endpoint compression via YUNIKORN-2249 did not check the wrapped handler for compression. This caused the metrics endpoint /ws/v1/metrics to be compressed twice resulting in scraping failures.

The issue was introduced in YuniKorn 1.9.0. See YUNIKORN-3341 for details.

Replaced btree implementation​

The btree implementation used in the core for the nodes was no longer maintained. The implementation has been swapped out for a maintained implementation. The new tree is generics based which provides a small improvement on both memory usage and performance. See YUNIKORN-3323 for details.

Podman support for builds and e2e test​

Besides Docker, Podman is now supported for building yunikorn-k8shim and running e2e tests. The release process and yunikorn-web build support is planned for the next release. See YUNIKORN-3441 for details

Configuration checksum checks​

The queue configuration in the configmap has supported checksum since YuniKorn 0.11. During configuration reload the checksum was calculated but not used. If the checksum is unchanged, the queue configuration has not changed. Checking the checksum before updating the queue structure in memory prevents a queue config reload from being processed when nothing changes.
See YUNIKORN-3347 for details.

Dropping managedFields from objects​

Kubernetes tracks who manages a field in an object to support SSA (server side apply) handling in the managedFields field. The content of this field can become large, and is not relevant during the scheduling cycle. To reduce overhead and lower the memory footprint the field is now removed before the object is stored in the shim cache. See YUNIKORN-3447 for details.

Reproducible build for release binaries​

The release process, starting with 1.10.0, will use reproducible builds for all the convenience images published. See YUNIKORN-3340 for details.

Deprecations​

Removal of the debug redirect​

As part of the changes to not expose the debug details via an open redirect in YUNIKORN-2965 the existing REST endpoints were deprecated. The redirect will be removed in YuniKorn 1.11. Documentation updates have already been made and no longer show the old REST endpoints. See YUNIKORN-3475 for details.
